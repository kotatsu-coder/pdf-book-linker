# 要件書：スキャン本の PDF を電子書籍ビューアのように行き来できる PDF にするシステム

（開発開始時の要件定義。現状の実装範囲は README を参照）

## 1. 背景と最終目標

- Windows PC・Python ローカル処理。紙の本をスキャンしてPDF化し、iPad の Goodnotes で閲覧・書き込みする。
- 電子書籍ビューアのように、目次・索引・図表・本文を自由に行き来できる PDF を自動生成したい。
- 入力 PDF の状態は未確定：画像のみのスキャンPDF／OCR済みPDF／テキスト埋め込みPDF のいずれにも対応できる設計。
- 将来は大量の本をバッチ処理。
- **独自ビューアは作らない。Goodnotes で使える標準 PDF を生成する。**

最終的に備えたい機能：
1. クリック可能な目次
2. 階層型PDFしおり（アウトライン）
3. 本文と図表の相互リンク
4. 巻末索引から本文へのジャンプ
5. 各ページから目次・索引への移動
6. OCR による全文検索
7. 印刷ページ番号と PDF ページ番号の自動対応
8. Goodnotes で利用可能な PDF 内部リンク
9. 元のページレイアウトを可能な限り維持
10. 複数の本を処理するバッチ機能

## 2. 主要機能

### 2.1 目次リンクの自動生成
- OCR 済み文字列から目次項目を検出し、座標を取得する。
- 章・節・項の階層を認識する。
- 印刷ページ番号を解析し、PDF ページ番号に変換する。
- 目次項目の座標に透明なリンク領域を追加。リンク先はページ先頭または見出し位置。
- 日本語の本：縦書き・横書き、複数段組、ページ番号の表記揺れ（リーダー「……」、全角数字等）に配慮。

### 2.2 PDF しおりの自動生成
- PyMuPDF 等で階層型アウトラインを追加。Goodnotes 取り込み後にどこまで使えるかも検証対象。

### 2.3 本文と図表の相互リンク
- 本文中の「図3-2」「表4-1」「Fig. 2」等を検出し、対応する図表キャプションへジャンプ。
- 図表番号検出、キャプション抽出、参照との対応付け、同一ページ内／別ページリンク、重複番号・章ごとの番号リセット、誤検出防止の信頼度スコア。
- 「元の位置に戻る」は Goodnotes 側の制約を考慮し、実現可能な代替案を検討（例：図表側に「参照元へ」リンクを置く 等）。

### 2.4 巻末索引のリンク化
- 例：「見出し語 …… 125, 128, 132」の各ページ番号をそれぞれ独立したクリック領域にする。
- 索引領域検出、見出し語とページ番号の分離、複数ページ番号、ページ範囲（125–128 等）の処理、座標対応付け、透明な内部リンク。

### 2.5 ナビゲーションボタン
- 各ページ余白に「目次へ」「索引へ」「章の先頭へ」。
- 元の文字・図表・書き込み領域を妨げない。Goodnotes 上での操作性（位置・大きさ）を重視。

## 3. OCR・文書解析

### 3.1 OCR エンジン比較
PaddleOCR / Tesseract / OCRmyPDF / その他（例：YomiToku, ndlocr 等）。比較項目：日本語精度、専門用語、縦書き、文字座標の取得、表・段組、Windows 導入難易度、CPU/GPU、速度、ローカル実行可否。**文字・単語単位の座標情報の保持を重視。**

### 3.2 ページ番号の対応付け
- 印刷ページ番号と PDF ページ番号の対応表を作る（単純な固定オフセットだけでなく）。
- ページ番号欠落、ローマ数字の前付け、章ごとのリセット、見開きスキャン、白紙ページ、欠損・重複、複数巻の結合に配慮。
- OCR で読み取ったページ番号と周辺ページの連続性から自動で対応表を作成。

## 4. PDF 処理技術
- 候補：PyMuPDF（解析・内部リンク・しおり・座標）、pypdf、OCRmyPDF、OpenCV、Pillow、PaddleOCR、SQLite（解析結果・対応表の保存）。
- 内部リンクは GoTo アクション。PyMuPDF `insert_link()` 中心。座標系、0始まり/1始まり、ページ回転、CropBox に注意。
- 品質維持：元画像を再圧縮・再描画しない。解像度・ページサイズ維持。リンク注釈を追加するだけ。OCR が必要なら検索用テキストレイヤーを追加。**元ファイルは上書きしない。** 処理後のファイルサイズ増加も評価。

## 5. Goodnotes 互換性（最重要）
実機で検証できるテスト PDF と確認手順を設計する：
1. 内部リンクのタップでページ移動できるか
2. 読み取り専用モードで動作するか
3. 編集モードでのリンク操作
4. 階層型しおりが認識されるか
5. OCR 文字検索が使えるか
6. 手書き注釈を追加してもリンクが機能するか
7. 再エクスポートでリンクが保持されるか
8. 数百〜数千ページで快適か
9. ページ回転・見開き表示でリンク位置がずれないか

**未検証の機能を「確実に動作する」と断定しない。PDF アウトラインと Goodnotes 独自のしおり・アウトライン機能を区別する。**

## 6. パイプライン
入力PDF → PDF構造解析 → OCR要否判定 → OCR・レイアウト解析 → 目次・索引・見出し・図表の抽出 → 印刷/PDFページ対応付け → リンク候補生成 → 誤検出・信頼度チェック → リンク・しおり埋め込み → PDF構造検証 → 出力。
各工程を独立モジュールにし、途中結果を保存して再実行できること。

## 7. 大規模 PDF
メモリ抑制、ページ単位処理、OCR キャッシュ、中断再開、並列処理、CPU/GPU 最適化、バッチ、ログ、エラーページ記録、元PDFと生成PDFの整合性チェック。将来の分散（別ミニPC）は考慮のみ、最初は実装しない。

## 8. ユーザーによる修正
目次項目とリンク先の修正、オフセット変更、章タイトル修正、不要リンク削除、図表対応の修正、生成前プレビュー。最初は JSON/CSV/簡易 CLI。将来 Streamlit / PySide6。

## 9. 開発フェーズ
- Phase 1 (MVP)：PDF読込、手動指定した目次項目への内部リンク、階層しおり、印刷/PDFページ対応、リンク付きPDF出力、Goodnotes 実機検証。
- Phase 2：OCR による目次抽出、ページ番号自動認識、章・節の階層解析、自動リンク、誤認識の修正。
- Phase 3：索引解析、図表対応付けと相互リンク、ナビゲーションボタン。
- Phase 4：バッチ、OCR キャッシュ、GUI、速度最適化、進捗可視化。

## 10. テスト
リンク先ページの存在、目次項目とリンク先の一致、クリック領域が意図した文字列に重なるか、リンク重複なし、ページ数維持、画像品質維持、OCR テキスト座標と画像の一致、Goodnotes での動作、大容量で停止しないか。
**低信頼度のリンク候補は自動埋め込みせず、手動確認に回す。**

## 11. 方針
1. Windows でローカル実行 2. 無料・OSS 優先 3. 書籍データを外部クラウドに送らない 4. レイアウト・画質維持 5. Goodnotes 互換最優先 6. 大規模対応 7. OCR・AI は段階導入 8. DRM・アクセス制御の回避はしない 9. 個人利用前提・著作権配慮 10. 不確実な仕様は断定せず検証方法を示す
