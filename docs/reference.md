# 詳細リファレンス

README の続きです。自動判定の中身、上書き JSON の書き方、評価指標の読み方をまとめます。ページ番号はすべて **0 始まりの PDF index** です。

## 1冊ずつの自動設定とビルド（autoconfig / build）

既存の文字層がある本は、次の1コマンドで検出・リンク追加・画像ストリーム検証まで実行できます。既定動作は完全オフラインで、AI/LLM・ネットワーク・OCRサービスを使用しません。

```powershell
uv run pdf-book-linker build "入力.pdf" -o "output/入力_linked.pdf"
```

設定と候補だけを確認するとき：

```powershell
uv run pdf-book-linker autoconfig "入力.pdf" --report-root "output/report"
uv run pdf-book-linker build "入力.pdf" -o "output/入力_linked.pdf" --config "override.json" --report-root "output/report"
```

自動判定するのは、ヘッダー・フッターの印刷ページ番号と区間対応、前方の複数ページ目次と階層、扉の小目次、後方の多段索引、本文のページ参照（「参照頁」列を含む）、ナビの大きさと空き余白です。座標はページの縦横比率で判定し、回転したPDFは表示方向で読み順を解析します。ナビの位置と大きさは後述の「フォルダ一括評価と本ごとのナビ配置」と同じ方法で、本ごとに決めます。空き余白が見つからないページではボタンを置かず、要確認にします。任意の履歴に戻る機能はありません。

作業結果は `work/auto/<book_slug>/` に保存します。

- `config.json`：再実行できる自動設定。`automatic: true` の設定は `stage3 --config` でも実行可能です。
- `pagemap.json`：編集可能なページ対応区間。
- `stage3_candidates.json` / `outline.json`：信頼度・理由・移動先・承認状態を含む候補。
- `decisions.json` / `nav_margin_stage3.json`：ページ判定の根拠と余白の測定。
- `metrics.json` / `autoconfig_report.md`：ページ対応の被覆率・観測一致率、目次件数・階層、移動先照合率、索引・本文参照件数、review件数、時間・プロセス最大メモリ。
- `words/`：ページ単位の抽出キャッシュ。入力の絶対パス・サイズ・更新時刻・スキーマ版が変われば無効化します。
- `stage3_verify.json`：build後のリンク・アウトライン・ページ形状・画像ストリームと元ファイルの不変性の検証。

`--report-root` 指定時は、その配下の書籍別フォルダにも設定・指標・日本語レポートと小さなプレビューPNGを保存します。`autoconfig` は完成PDFを書きません。`build` が指定した1つの出力を作ります。画像は再圧縮・置換せず、元PDFと同じ出力パスや同一実体への保存は拒否します。書籍データ・中間JSON・PDFはコミット対象外です。

手動JSONは指定した項目を自動設定へ再帰的に上書きします。例えば：

```json
{
  "toc_pages": [4, 5],
  "part_pages": [6, 36],
  "index_pages": [233, 234],
  "pagemap": "work/book/pagemap_edited.json",
  "toc_ymin_ratio": 0.035,
  "index": {"columns": 2, "ymin_ratio": 0.035, "ymax_ratio": 0.965},
  "nav": {"tap_size": 24, "gap": 8}
}
```

ページはすべて **0始まりのPDF index** です。矩形は回転前の元PDF座標です。`tap_size` と `gap` は先頭ページのpt値を基準に他ページへ比例適用します。`candidate_overrides` は Stage 3 と同じID別補正JSONです。従来の完全なStage 3手動設定（`extract_output` を含む設定）を `build --config` に渡す場合は、従来の実行経路と手動補正を優先します。この場合は従来設定に従って抜粋PDFも作ります。

**限界と評価の読み方**：文字層があるページが半分未満なら「OCR が必要」と表示して終了コード **3** で停止します。通常の入力・設定エラーは2、PDF検証不合格は1です。文字層があってもOCR誤字・番号欠落・章ごとの番号リセット・縦書き・見開き・特殊な段組では設定やページ対応の補正が必要です。番号観測が全く取れない場合は、目次タイトルが本文上部に一意に現れる複数の一致から一定オフセットを推定できることがあります。この場合は根拠を別途記録します。

照合率は全抽出候補が分母で、未解決も不一致です。タイトル・語の正規化後の一致、または二文字連鎖の70%以上一致で目次の移動先/次頁、索引の移動先/前頁を照合します。索引の承認判定にはStage 3互換の短い語幹照合も併用するため、照合率と承認率は別の指標です。被覆率・一致率は自己評価であり正解率ではありません。検出ゼロも対象が存在しない証拠にはなりません。低信頼度・重複・重なりはreviewに残し、埋め込みません。Goodnotesでの動作は実機未検証です。

デモ生成器はPyMuPDF同梱CJKフォントの同一データを描画と透明文字層へ埋め込みます。Windowsフォントへの依存はありません。任意のフォントを使う場合は `--font "フォントファイル"` を指定します。テストではデモ生成器の目次・索引配置・本文参照の正解と移動先を全件比較します。

## フォルダ一括評価と本ごとのナビ配置（batch）

```powershell
uv run pdf-book-linker batch "書籍フォルダ" --report-root "output/report" --work-root "work"
# 同じコマンドで再開。全冊をやり直すときだけ --force。
uv run pdf-book-linker batch "書籍フォルダ" --report-root "output/report" --override-root "work/overrides"
# メモリに余裕があれば --jobs 3（1〜4、既定1）。大部書籍も1冊1プロセス。
```

サブフォルダを含む全 PDF を、1冊ずつ別プロセスで解析します。バッチでは完成PDFを作りません。`summary.md` とExcelでも読めるUTF-8 BOM付き `summary.csv` は失敗・要確認の順で更新します。入力のパス・サイズ・更新時刻、Python実装全体、書籍のoverride内容が同じで、結果ファイルが残っていればスキップします。同じslugになる同名書籍は衝突を通知するので、フォルダ単位を分けてください。画像・文字層・中間データは外部送信しません。

`ok` はページ対応90%以上、目次照合85%以上、索引照合80%以上（索引候補なしは除外）、非ナビ候補のreview比率10%以下、ナビ省略5%以下、目次検出ありです。`needs review` は条件未達、`OCR required` は文字層が半数未満、または末尾12頁の8頁以上で欠落、`failed` は例外等による処理失敗です。末尾の判定は索引の実在を保証するものではありません。「索引なし」と「索引検出失敗」は区別しきれないため、okも人の確認を省く保証には使えません。再実行は入力ファイルの更新時刻を保持したまま内容だけ書き換える運用には対応しません。

印刷番号の単語が同じ行に分割されても、間隔が数字幅の1.2倍以内なら結合します。周囲のドットは無視します。印刷番号の被覆が90%未満なら、目次タイトルと本文上部・柱の一致から印刷番号とPDF番号の差を投票します。3項目以上の支持が必要で、外れ値を除外し、支持区間が重ならない場合は区分的な差も扱います。前後の挿入ページを観測できない区間は推定の限界を記録します。近傍でも連番として支持される印刷番号でクロスチェックし、80%未満の一致なら推定を棄却します。方式、支持数、信頼スコア、クロスチェック数を `metrics.json` に記録します。観測なしを一致100%とは表示しません。

目次の点線の後ろにある著者名はタイトル照合から除外します。索引の段境界は単語の空白帯と行頭位置から推定し、固定の1/2・1/3に依存しません。本文の単位付き参照を維持し、「参照頁」の表は列幅と次の同列見出しまでに制限して同じ列の重複抽出を防ぎます。奥付をPARTにしないよう後付け領域を除外します。照合率は既存OCR層を使う代理指標です。画像にあってもOCRにない見出しや、本文に別名しかない索引語は不一致のまま残ります。

ナビは左右それぞれ最大16頁を均等に採り、下中央・下外側・上外側・外側縦積みの4候補を比較します。各候補の空白率、余裕の下位10%点、平均を `navigation.json` に保存します。印刷番号からPDFの左右の偶奇を推定し、各側で位置を固定します。全対象頁の元画像を解析用に800px幅でレンダーし、文字・柱・ページ番号・暗い番号箱・タブと重なる場合だけ横または縦へページ幅の1–2%ずらし、それでも印字があればその頁は省略します。白い紙の余白に加えて、ページ自体の背景色と同じ色で平らな部分（濃い色の扉など）も空きとして扱います。ただし、その平らな部分がページの端まで続いている場合に限ります。周囲と色の違う塗りつぶしの箱や、余白の内側にある写真の暗い部分は印字とみなします。低解像度解析なので細い淡色印字には限界があり、左右の本文プレビューも確認してください。保存時の元画像は再描画・再圧縮しません。

ボタンの大きさは「表示時のページ幅」を基準にします。縦長のページはページ幅、横長や正方形に近いページはページ高さの0.75倍を表示幅とみなし（縦向きの iPad に収めたときの幅）、その5.5%を一辺とします（16〜150pt）。11インチ iPad では約9mmで、Material Design のタッチ領域の推奨（48dp）に近い大きさです。Apple の最小推奨（44pt、約7mm）を下回らないよう、余白が狭いページでも `min_size`（既定 0.045）より小さくはしません。ボタン間は表示幅の1.2%です。単位は表示時の目安で、iPadやGoodnotesでの実測値ではありません。

左右それぞれの基本の位置は全体で1つに決め、読む人が場所を覚えられるようにします。あるページでその位置に余白がないときは、次の順に試します。(1) 同じ位置で少しずらす、(2) 同じ位置で `min_size` まで段階的に小さくする、(3) 空きの多い順にほかの位置を試す（位置を設定で固定している場合は行わない）、(4) それでも置けなければ省略（既定）。`"crowded":"overlay"` を指定すると、(4) の代わりに、ページの背景色の不透明な下地を敷いて基本の位置に描きます。この場合は下の印字が一部隠れるので、検証でも重なりを許可し、報告に記録します。各ページで使った位置・大きさ・方法は `navigation.json` の `fallback`（none / smaller / other-position / overlay / skipped）に残します。

`"style":"pill"` を指定すると、電子書籍アプリの操作ボタンのような半透明の角丸の下地に矢印を描きます（明るいページでは濃い下地に白い矢印、暗いページでは明るい下地に濃い矢印）。既定の `"line"` は、下地なしの薄い矢印です。

ボタンの色と濃さは、ページごとにボタンの下の背景色を測って自動で決めます。明るい背景には濃い線、暗い背景には白い線を使い、背景とのコントラスト比（WCAG の基準）が `contrast`（既定 3.0）に届く最小の不透明度（0.25〜0.9）を選びます。目立たせたいときは `contrast` を上げ（例：4.5）、控えめにしたいときは下げます（例：2.0）。`color` に `"#RRGGBB"` か `[r,g,b]` を、`opacity` に 0〜1 の数値を指定すると固定できます。各ページで選んだ色・不透明度・背景色・コントラスト比は候補 JSON の `style` に記録します。

自動ナビの上書き例：

```json
{"nav":{"position":{"left":"bottom-outer","right":"outer-edge"},"size":0.055,"contrast":4.5}}
{"nav":{"color":"#1a3c8c","opacity":0.4}}
```

`position` は両側共通の文字列でも指定できます（`bottom-centre`, `bottom-outer`, `top-outer`, `outer-edge`）。`size` は1以下ならページ幅比、1より大きければPDFのpt値です。手動上書きでも印字との衝突検査は行います。`--override-root` のファイル名は `<book_slug>.json`。目次・索引範囲やpagemapパスなど従来の上書きも併用できます。

```powershell
uv run pdf-book-linker build "入力.pdf" -o "output/入力_linked.pdf" --work-root "work" --report-root "output/report"
uv run pytest -q
```

buildでは全画像・soft maskの圧縮ストリーム、元PDFの前後ハッシュ、全リンク・アウトライン・形状を再検証します。strict検証では元画像とナビ矩形の衝突も検査します。Goodnotes実機動作は未検証です。

目次見出しだけOCRが欠ける本では、既設のローカルTesseractを任意で利用できます。上書きJSONに `{"heading_ocr":{"height_ratio":0.14,"language":"jpn+eng"}}` を指定すると、文字層だけでは不一致だった目次の移動先について上部14%だけを再照合します。元の文字層だけの値を `toc_text_layer_hit_pct`、画像OCR併用後を `toc_target_hit_pct` に分け、範囲・回数・エラーも報告します。追加インストール・外部送信・元PDFへのOCR層追加は行いません。Tesseract未導入・指定言語なしの場合は元の指標を維持します。見出しOCRの結果は `work/<book>/heading_ocr/` のJSONから確認できます。画像のみの本の一括OCRには使いません。

OCRが目次の数字列を縦書きと誤認している本では `{"toc_number_ocr":true}` を指定できます。目次の右端10%だけを既設Tesseractの数字限定モードで再計測し、元の見出し行の近くにある数字と座標を使います。処理範囲・数値・座標は `toc_number_ocr/` のJSON、実行状況は各冊レポートに保存します。本文や索引のOCRには使いません。固定位置の数字列に限る補助で、レイアウトの異なる本へ一律には適用しません。

数字列が端から内側にある本では `"toc_number_ocr":{"x0_ratio":0.85,"title_xmax_ratio":0.70}` のように指定できます。左から85%以右を数字用に解析し、タイトルは70%までで区切って著者列を除きます。実際の数字列・著者列を画像で確認して設定してください。

短い手動補正は `{"pagemap":{"segments":[{"pdf_index0_start":8,"pdf_index0_end":218,"print_start":1,"style":"arabic"}]}}` のように直接書けます。範囲は `"toc_page_range":[1656,1693]` / `"index_page_range":[1694,1744]` で両端を含めて指定できます。手動ページ対応に合わせて本文・索引の印刷番号範囲も再計算します。索引の `20i,22i` のような図表ページの付記iは番号から除外し、数字だけにリンクします。

上下巻で共通の索引は `{"index":{"volume":"I"}}` または `"II"` を指定します。`12(I),14(II)` を別々の参照として読み、自巻だけを解決します。別巻・巻表記不明はreviewに残し、同じ数字の自巻ページには結びません。`index_local_volume_hit_pct` と別巻件数を別記し、従来の索引照合率は別巻も分母に残します。標準内部リンクだけでは別PDFへ移動できないため、両巻共通索引は完全解決にはなりません。

本文の「教科書」「第N版」「出版年」「別書名」などで外部書籍の引用と分かるページ参照は、自書へ結ばずreviewに下げます。改行直前の引用文脈も確認しますが、書名が省略された引用をすべて判別する保証はありません。明示的な「本書」「本章」の内部参照と、参照頁列は維持します。

別冊図版を末尾に収めたPDFは、手動pagemapの区間に `"prefix":"図版:"` を指定して本文と同じ番号の衝突を避けます。`"nav":{"extra_starts":[1522]}` のように追加区分の先頭index0を指定すれば、章ナビでもその区分を扱えます。図版の個々の図番号を本文ページ番号として自動解決する機能ではありません。

## 低レベルのコマンド

`inspect` / `apply` / `verify` / `extract` / `stage2` / `stage3` は、目次や索引を手動 JSON で指定して処理する初期の経路です。通常は `build` と `batch` で足ります。JSON の書式と座標系は [design.md](design.md) を参照してください。各コマンドの引数は `uv run pdf-book-linker <コマンド> --help` で確認できます。
