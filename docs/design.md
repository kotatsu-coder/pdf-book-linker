# 設計書：標準 PDF によるスキャン本のナビゲーション

2026-11-05、Stage 1 / Phase 1。要件書の構造解析、手動ページ対応、目次リンク、階層しおり、Goodnotes 検証を対象とする。書籍データはローカルのみで扱う。

## 実現性（要件 Step 1）

PDF の `/Outlines` は文書内の階層目次である。Goodnotes 自身のブックマークやアプリ内アウトラインとは別物であり、相互変換・取り込み・再出力の保持を前提にしない。本表の Goodnotes 欄はすべて実機 **未検証**。PDF 構造検証の成功はアプリ互換性の証明ではない。

|電子書籍ビューア風の機能|標準 PDF での実現性|Goodnotes / 制限|
|---|---|---|
|目次タップで本文へ|再現可能：透明な GoTo リンク注釈|未検証：タップ方法、読み取り・編集モード差|
|章・節の階層しおり|再現可能：`/Outlines`、日本語タイトル|未検証：階層表示、Goodnotes 独自項目との区別|
|索引の各数字から本文へ|再現可能：各数字の座標に独立リンク|未検証：小さい数字の押しやすさ。実装は Stage 3|
|本文と図表の相互参照|再現可能：対応する座標への固定リンク|未検証：同一ページ位置への移動精度。実装は Stage 3|
|各ページの目次・索引ボタン|再現可能：余白への静的描画とリンク|未検証：書き込み干渉。実装は Stage 3|
|全文検索|テキスト層があれば可能。画像のみなら OCR が必要|未検証：日本語検索、既存 OCR の誤字、再出力|
|印刷番号と PDF 番号の対応|再現可能：区間と明示ラベルで変換|未検証：アプリに印刷番号が表示されるとは限らない|
|画像とレイアウトの保持|再現可能：画像ストリームを変えず注釈を追加|未検証：取り込み・再出力時の品質|
|任意の「元の位置へ戻る」履歴|制限あり：PDF に汎用の動的閲覧履歴は持たせない|未検証：アプリの戻る機能。固定参照元リンクを代替候補とする|
|動的な図表ポップアップ・辞書・表示切替|困難：標準的な内部リンクの範囲外|未検証：JavaScript 等には依存しない|
|数百〜数千ページの快適さ|構造上は可能、画像サイズ・端末資源に依存|未検証：数百ページ規模の試作後、大容量で時間・メモリを測定|
|書き込み後のリンクと再エクスポート|PDF は注釈とリンクを併存可能|未検証：Goodnotes の保存形式や出力条件に依存|

## 技術選択（要件 Step 2）

Python 3.12 と uv を使用する。PyMuPDF は既存テキストと座標、ページ構造、GoTo、`set_toc()`、生画像ストリーム取得を一つの API で扱えるため採用。実行環境の依存は `uv.lock` に固定する。配布時は PyMuPDF のライセンス条件を別途確認する。JSON は人が編集でき、工程間の契約にも使える。MVP は標準ライブラリの argparse、pathlib、hashlib を中心とし、画像加工や外部 AI を必要としない。pypdf は将来の独立検査候補、OpenCV / Pillow は解析画像用の候補で、元ページ画像の置換には使わない。SQLite は大量処理の管理用途に留保する。

## アーキテクチャ（要件 Step 3）

工程は「元 PDF → 構造検査 → 既存テキスト利用 / 将来 OCR → 手動または候補 JSON → ページ対応 → 解決済みリンク → PDF 保存 → 独立検証」とする。書籍ごとに `work/<book>/` を分け、別の書籍の JSON を混ぜない。MVP は手入力 JSON が工程の入口になる。

|モジュール / 工程|入力|保存する出力|依存・状態|
|---|---|---|---|
|`inspection` / inspect|元 PDF|`inspect.json`：ページ数、サイズ、回転、CropBox、MediaBox、画像数、テキスト有無、アウトライン、リンク数|PyMuPDF。ページ単位処理|
|`pagemap`|`pagemap.json` の手動区間|同じ JSON を編集して再利用|独立した双方向変換。未定義はエラー|
|手動目次仕様|既存テキストとページ画像のローカル確認|`toc.json`、必要なら `toc_text.json`、根拠メモ|MVP は人が決定。抽出器は未実装|
|`linking.resolve`|元 PDF、目次、ページ対応|`apply.json` 内の `resolved` / `review`|信頼度の低い項目は status=review、埋め込まない|
|`linking.apply_pdf`|解決済み仕様|別名 PDF、`apply.json`|GoTo とアウトライン。元ファイルは読み取りのみ|
|`verification`|出力、元 PDF、同じ仕様|`verify.json`|再オープンして検証。成功判定とエラー一覧|
|`extraction`|元 PDF、選択 index0、目次・対応|抜粋 PDF、`extract_toc.json`、`extract_pagemap.json`、`extract.json`|抜粋後に apply と verify を実行|
|将来 `ocr` / `layout`|ページ画像、OCR 設定|`ocr/pages/<pdf_index0>.json`：文字・単語・行座標、信頼度、エンジン版|Stage 2。MVP は実装しない|
|将来 `detectors`|OCR / 既存文字座標|`toc_candidates.json`、`page_number_candidates.json`、`index_candidates.json`、`figure_candidates.json`|Stage 2–3。各候補に evidence / confidence / status|
|将来 `planner`|承認済み候補とページ対応|`link_candidates.json`、`review.json`|共通のリンク仕様へ変換して既存の保存・検証器に渡す|

各 JSON は `schema_version` を付けて拡張する。MVP の単純配列 toc も受け付ける。既存の `/Outlines` は apply で仕様全体に置換する。既存リンクは保持するが、新リンクと重なる場合は失敗させる。verify はすべてのリンクを GoTo として検査するため、外部 URI 等を含む入力は検証不合格となる。汎用文書対応でこの方針を変更する際は明示オプションを設ける。

### ページ対応の契約

```json
{"schema_version":1,"segments":[
  {"pdf_index0_start":0,"pdf_index0_end":3,"print_start":1,"style":"roman"},
  {"pdf_index0_start":10,"pdf_index0_end":239,"print_start":1,"style":"arabic"}
]}
```

内部 index は必ず 0 始まり、末尾を含む区間。`print_start` は整数、`roman` / `ROMAN` / `arabic` を使用。全角数字や Unicode ローマ数字は NFKC 正規化する。区間の重複・ラベル重複は拒否。章ごとのリセットは `prefix`（例 `章2:`）で区別する。欠損・白紙は区間を分け、未対応 index の逆引きは null 相当、未対応ラベルの順引きはエラー。MVP は 1 印刷ページ対 1 PDF ページのみ。見開き分割・同番号重複は将来 `page_regions` と明示候補 ID で表し、曖昧なラベルで自動ジャンプしない。

### 目次仕様と座標

```json
{"schema_version":1,"entries":[
  {"title":"第1章","level":1,"print_page":"1",
   "source":{"pdf_index0":4,"search":"第1章"},"dest":"top","status":"approved"},
  {"title":"第1節","level":2,"print_page":"2",
   "source":{"pdf_index0":4,"rect":[100,200,600,240]},"dest":{"y":150},"status":"approved"}
]}
```

`search` は既存テキスト層の一意な検索結果を要求する。複数一致・不一致はエラー。`rect` は人が画像とテキスト座標を照合する。数値座標は PyMuPDF の **回転前、CropBox 左上を原点、右向き x・下向き y、pt**。MediaBox 絶対座標や回転後の画面座標を直接渡さない。画面座標は `derotation_matrix` で変換する。CropBox のオフセットを二重加算しない。dest の y もリンク先の同じ座標系。編集時は全ページの回転をメモリ上だけ 0 にし、保存前に元の回転を戻す。0/90/180/270 度と非零 CropBox を合成 PDF で検査する。`set_toc()` に渡すページ番号だけ API に従い 1 を足す。

`set_toc()` で階層を作成した後、CropBox の原点ずれを扱うため、各アウトラインの `/XYZ` をリンク先ページの `transformation_matrix` の逆行列で得た PDF 座標へ設定する。階層は 1 から始めて最大 1 ずつ深くする。`status` が approved 以外の項目は review に隔離する。省略は手動承認扱いなので、自動検出器は必ず status を明示する。矩形はページ内であり、既存文字の少なくとも一つと重なる必要がある。これは意味的一致の自動保証ではない。画像と実見出し・ページ番号の照合は手動レビューの責務である。

### 保存・検証・失敗時の再実行

入力と同一パス・同一実体への保存を拒否し、既存出力も拒否する。保存は出力ディレクトリの一時ファイルへ `garbage=0, deflate=False` で新規保存し、成功後に置換する。画像再描画・最適化・再エンコードはしない。全ページについて画像と soft mask の **圧縮済み生ストリーム SHA-256** を比較する。PDF のファイル全体は構造更新で変化するため、全体ハッシュは元ファイル不変の確認に使う。

verify は GoTo 種別、範囲内の移動先、指定移動先 y、矩形一致・元テキストとの重なり、重複、透明境界線、総リンク数、アウトラインの件数・階層・タイトル・ページ、ページ数・回転・Box、画像一致、サイズ増減を検査する。不合格は終了コード 1、入力・処理エラーは 2。JSON は一時ファイルから置換する。処理エラーではメッセージを出し、未完成 PDF を最終名にしない。検証不合格の PDF は調査用として残るので Goodnotes への持ち込み対象にしない。

MVP はコマンド単位の再実行。JSON 修正後に新しい出力名で apply → verify する。全処理のチェックポイント再開や OCR は未実装。Stage 2 では元ファイルハッシュ、エンジン・モデル版、設定ハッシュをキャッシュキーにし、ページごとの成功/失敗を記録する。Stage 4 で再開台帳を導入する。巨大 PDF は画像・テキストを全ページ分メモリ保持せずページ単位で処理する。書籍データ・抽出 JSON・PDF は `.gitignore` で除外し、クラウドへ送信しない。

## Goodnotes 検証（要件 Step 5）

小さな抜粋は目次 2 ページ、各 PART の扉と代表本文、その他のページを含む。リンク先が抜粋に存在する項目だけを再配置し、全項目を残すことで抜粋外へ誤ジャンプさせることはしない。抜粋の source index は `extract.json` で元 PDF に逆引きできる。抜粋の検証はリンク追加前の抜粋と比較し、元 PDF からの画像コピー一致も試作記録に残す。

`docs/goodnotes_checklist.md` の 9 項目を実機で実施する。小さい抜粋は操作互換性、数百ページ規模の版は性能に使う。数千ページの性能、iPadOS / Goodnotes の版差、再エクスポート後の保持は未検証。実機結果を記録してから後段の実装方針を確定する。

## Stage 2 実装（2026-11-05）

前記の Stage 2–3 の予定に対し、既存 OCR を使う目次・小目次・索引・ナビを先行実装した。ローカル OCR エンジン比較や図表相互参照は引き続き対象外。Stage 1 内部リンクはユーザー実機で動作良好との報告があるが、新しい領域・索引・ナビは未検証。

`stage2.py` は「extract_toc / manual_toc / extract_index → 候補 JSON → validate_plan → apply_candidates → verify_candidates → 抜粋再配置 / プレビュー」の工程を提供する。CLI は `stage2 --config <JSON>`。既存 Stage 1 CLI と単一矩形仕様は保持する。

候補の契約は `kind`（toc / part_toc / index / nav）、0 始まりのリンク元・リンク先、`rect`、`intended_box`、`confidence`、`status`、`method`。目次には `role=title/number`、ナビには `button=0..3` を持つ。信頼度 0.95 以上かつ approved だけを保存する。元手動目次の review も統合候補に保持する。`--reuse-candidates` で人が修正した統合 JSON を優先し、再抽出を省略する。ナビの完全性と移動先の検証は省略しない。

行は rawdict の文字中心 y でまとめ、索引では x による段分割と原文字の空白・座標の間隔を用いる。見出しと末尾の数字を分離し、ドット列を除外する。OCR が点線を含む長い span を均等字幅にしてしまう場合には、行画像の暗いピクセルの連結成分の高さを測り、点線より背の高い印字を見出しの左右端とする。数字は対応文字範囲の画像外接枠で仕上げる。全矩形に既定 3 pt の余白を付ける。解析レンダーは元 PDF の画像を置換しない。NumPy を追加できないネットワーク制限環境でも動くよう、Pixmap の samples を標準 Python で処理する。

索引は NFKC と元文字位置の対応表を持ち、全角数字、l/I→1、O/o→0 を認識する。リストは個別リンク、範囲は全範囲の矩形で先頭にリンク。範囲逆転・範囲外・語中の数字・数字列に続く非数字は review。OCR 英字補正は confidence=0.86 として人の確認が必要。印刷番号の妥当範囲は設定と pagemap の両方で制限する。OCR 自体が数字を誤って別の有効数字にした場合の完全検出や、欠落文字の復元はできない。

ナビは元コンテンツとは別のベクター線コンテンツを追加する。gray=0.8（白に対して 20% の濃さ）、文字・フォントなし。静的コンテンツなので印刷にも現れ、注釈外観の扱いに依存しにくい。GoTo は各 110×110 pt 以上の透明矩形。本文の左右ノンブルを避けた中央帯を、左右ページと扉を含む全対象ページで画像測定する。濃い印字との重なりで停止し、見切れや淡色印字はプレビューで併せて点検する。位置・大きさ・線幅・濃さ・閾値は設定可能。

保存は従来と同じ `garbage=0, deflate=False`。元画像と soft mask の圧縮済みバイト列を全ページで比較し、元 PDF の全体ハッシュも前後で照合する。しおりの /XYZ は正式な座標変換で原点に設定する。検証用抜粋は全移動先を元 index0 から再配置し、未収録のリンクを削除する。削除内訳をレポートに記録する。一般化の限界は、目次ページ範囲・段数・抽出 y 範囲・本文範囲の指定が必要なことと、複雑な縦書き / 不規則な段組が未対応なこと。


## Stage 3 の処理と再実行

`stage3.py` は Stage 2 の座標・画像測定・安全保存・検証を共用し、本文ページ参照、索引の字間統合と移動先語照合、PART 単位ナビ、位置付きしおりを追加する。既存コマンドの再現性を維持するため Stage 3 を独立コマンドにした。

本文の文字は行末ベースラインで束ね、側端の PART タブを除く。ページ単位の正規表現だけでなく NFKC の元文字オフセット表を保持し、参照語だけの文字座標を使う。改行参照は同一の論理 ID に複数矩形を持つ。明示的なページ単位がない数は対象外。範囲外・逆範囲は rejected、OCR 補正は画像確認まで review。自動で文字を補正できたことだけでは高信頼度にしない。

索引は行末数字列に限定する。数字間の OCR 空白は座標上の字間 / 数字幅が設定閾値未満のときだけ統合し、カンマを消さない。移動先と直前ページに見出し語の先頭2〜4字がなければ confidence を最大0.8に下げる。OCR ごみを照合対象から除く。候補は保存し、削除しない。

ナビの starts は nav_unit=part なら PART 目次の移動先と最初の後付け節、chapter なら従来の全項目。PART の目次移動先が扉を指す場合は扉、扉のない本では最初の項へ手動補正する。最後の PART の次は後付け、続いて索引。検証では各ページから期待先を計算し直す。

しおりは `[level, title, PDFページ1始まり, y_pt]`。目次から印刷章番号を復元し、索引の左右段の見出しを読む順に付加する。同じ y の左右見出しを独立に扱う。文字位置に画像中の色付き字形を併用し、読めない字は review または根拠付き補正。章のタイトル画像が OCR にない場合はページ先頭にフォールバックし、本文やランニングヘッダーを見出しとしない。PDF /XYZ 座標は対象ページの変換行列から設定する。Goodnotes の y 反映は未検証。

manual_toc、ID ごとの pageref_overrides / candidate_overrides、全置換 outline_overrides を優先する。reuse でも override を再適用する。全体・抜粋は元ファイルや互いに同じ実体へ保存できない。保存後の再オープン検査でリンク相互重なりも検出する。目次数字の画像成分が全て数字枠に入るか再測定し、タイトルとの重なりも拒否する。画像ストリームは garbage=0 / deflate=False で保持する。
